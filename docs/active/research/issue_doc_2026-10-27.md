## 1. Tree Stump Display Scale

### Problem Summary
Tree stumps appear 2× to 3× larger on the board than they ought to be. Their source artwork is 32×32 pixels, but they are currently rendered at 128px (a 4× upscale), making them look out of proportion with trees, heroes, and surrounding tokens.

### Current Implementation & Root Cause
- **Asset Dimensions**: Stumps ([`t_stump_oak.png`](file:///c:/Users/16048/Projects/fantasy_guild_v2/public/assets/tokens/forest/t_stump_oak.png), [`t_stump_fir.png`](file:///c:/Users/16048/Projects/fantasy_guild_v2/public/assets/tokens/forest/t_stump_fir.png), etc.) are 32×32 pixel art.
- **Token Configuration**: In [`data/tokens.json`](file:///c:/Users/16048/Projects/fantasy_guild_v2/data/tokens.json#L3572-L3600), `token_oak_stump` and `token_fir_stump` are defined with `"size": 1`, but lack `"artSize": "small"`.
- **Rendering Engine**:
  - In [`src/config/matGeometry.js`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/config/matGeometry.js#L75-L160), default 1×1 tokens are standard tokens (`TOKEN_PX = 128`, `artRadius = 64`, `tokenBodyScale = 1`).
  - Standard tokens render at 128px across. A 32px sprite scaled to 128px receives 4× scaling instead of pixel art 2× scaling.
  - Setting `"artSize": "small"` designates the token as a small 1×1 token: `tokenBodyScale = 0.5`, `artRadiusOf = 32`, and renders at 64px across (exactly double the 32px raw sprite).

### Specification for Implementation
1. **Update Token Definitions** in [`data/tokens.json`](file:///c:/Users/16048/Projects/fantasy_guild_v2/data/tokens.json):
   - Add `"artSize": "small"` to `token_oak_stump`, `token_fir_stump`, and any future stump tokens.
2. **Review CMS Token Defaults & Fixtures**:
   - Check [`src/ui/dev/forestryDev.js`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/dev/forestryDev.js) and test fixtures to ensure stump instances specify `artSize: 'small'`.
3. **Verify Physics & Placement**:
   - Confirm that the halved art radius (32u instead of 64u) behaves correctly for stump placement, hero harvesting walk spots, nearby forest checks, and sapling growth.

## 2. Foundation Unbuilt State: Replace Yellow Warning with Large Gear on Hover

### Problem Summary
Foundations that need to be built currently display a yellow warning alert icon (`!`). When hovered, a gear icon appears *above* the warning alert icon, resulting in visual clutter with two stacked icons. The owner requested that on hover, the yellow warning icon should be **replaced** by the gear icon directly in place, and the gear icon should be displayed **fairly large**.

### Current Implementation & Root Cause
- **Problem & Gear Architecture**:
  - When a Foundation has no recipe/building chosen, [`problemOf`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/problemMark.js#L70-L83) flags `ALERT.CHOOSE_BUILD` (`severity: SEVERITY.WAITING`).
  - In [`src/ui/components/board/TokenBubbles.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBubbles.jsx#L247-L291):
    - At rest: `showProblem` is true, rendering [`ProblemMark`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/ProblemMark.jsx) in the middle row (`data-bubble-row="middle"`).
    - On hover: `showGear` is true (`!!gear?.show && !marked && isHovered`). Because `showRest` (which includes `showProblem`) is true, the hover row is pushed up via `hoverRowStyle`:
      ```javascript
      const hoverRowStyle = showRest
          ? { left: 0, width: boxPx, top: boxPx / 2 - restHalf - ROW_GAP_U, transform: 'translateY(-100%)', gap: ROW_GAP_U }
          : { left: 0, width: boxPx, top: boxPx / 2, transform: 'translateY(-50%)', gap: ROW_GAP_U };
      ```
    - This explicitly renders [`StationGearBadge`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBadges.jsx#L174) in a separate row above [`ProblemMark`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/ProblemMark.jsx).
- **Badge Size**:
  - In [`src/ui/components/board/TokenBadges.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBadges.jsx#L204-L235), `StationGearBadge` is rendered as a 28×28 button with a 24×24 gear image (`w-6 h-6`).

### Specification for Implementation
1. **Swap on Hover Behavior**:
   - In [`src/ui/components/board/TokenBubbles.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBubbles.jsx):
     - When a token has a build choice (`choose === 'build'` or `gear.isFoundation`) and is hovered, suppress the `ProblemMark` so it does not render simultaneously with the gear.
     - Place the gear badge directly in the centered middle position (`top: boxPx / 2, transform: 'translateY(-50%)'`) rather than an offset hover row.
2. **Increase Gear Display Size**:
   - In [`src/ui/components/board/TokenBadges.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBadges.jsx):
     - Provide an expanded/large sizing option for foundation gear badges (or a dedicated `large` / `isFoundation` scale factor), significantly larger than the standard 24px icon (e.g. 32px–48px art size with matching outline masks `gearOutlineStyle`).
3. **Verify Click & Tooltip Semantics**:
   - Clicking the replaced gear opens the foundation build picker (`onOpenRecipes` / `gear.onClick`).
   - Hover tooltip displays the build prompt ("Choose what to build").

## 3. Flag Sprite: 32px Pennant at Double Size (64px)

### Problem Summary
The game currently uses 64×64 multi-colored flag sprites displayed at 128px (2×). The owner has a smaller 32×32 raw pixel flag sprite located at `public/assets/ui/u_flag_pennant.png` and wants the ability to display this smaller pennant sprite at double size (2× = 64px). This connects directly to existing backlog ticket `T-150` ("Smaller hero flag").

### Current Implementation & Root Cause
- **Asset Comparison**:
  - Current flags: `public/assets/ui/u_flag_*.png` (`u_flag_base.png`, `u_flag_bluelite.png`, etc.) are 64×64 pixels.
  - Smaller pennant: [`u_flag_pennant.png`](file:///c:/Users/16048/Projects/fantasy_guild_v2/public/assets/ui/u_flag_pennant.png) is 32×32 pixels raw.
- **Flag Geometry & Sizing**:
  - In [`src/ui/components/board/flagGeometry.js`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/flagGeometry.js#L11-L19):
    ```javascript
    export const FLAG_PX = 128;
    export const POLE_BASE = Object.freeze({ x: 40, y: 116 });
    export const FLAG_CLOTH = Object.freeze({ left: 12 / 64, top: 11 / 64, right: 62 / 64, bottom: 36 / 64 });
    ```
    Constants assume 64×64 art drawn at 2× (128px).
  - In [`src/ui/components/board/FlagMark.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/FlagMark.jsx#L11), `size = FLAG_PX` (128px).
  - In [`src/systems/board/FlagColours.js`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/systems/board/FlagColours.js#L13-L37), `flagSpritePath` builds `/assets/ui/u_flag_${colour}.png`.

### Specification for Implementation
1. **Geometry Recalculation for 32px Pennant**:
   - For `u_flag_pennant.png` drawn at 2×, total rendered size is 64px.
   - Measure the exact anchor coordinates for the 32×32 pennant (pole base (x, y) and cloth bounds) to create geometry definitions for 64px flags.
2. **Flag Asset Strategy (T-150 / T-151)**:
   - Determine whether `u_flag_pennant.png` replaces all hero flags with dynamic color masking/palette swapping, or if colored versions of the pennant will be authored/referenced.
   - Update [`FlagMark.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/FlagMark.jsx) and [`FlagLayer.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/FlagLayer.jsx) to support the 64px display size (`FLAG_PX = 64` or variant).
3. **Verify Pinning & Idle Spot Alignment**:
   - In [`flagGeometry.js:pinnedFlagPoint`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/flagGeometry.js#L50), ensure that pinned flags sit cleanly on tokens of both standard (128px) and small (64px) art sizes.

## 4. Inconsistent Bar vs. Bubble Presentation on Unworked Tokens (Copper Ore Veins)

### Problem Summary
The project introduced the new **bar-style information / work plate** ([`WorkPlateLayer.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/WorkPlateLayer.jsx) & [`workPlate.js`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/workPlate.js)) to replace legacy circular bubble rings (`RingBadge`, `Bubble`, `TimerBubble`) on working tokens. Forestry and fishing tasks actively use this new bar format, but the owner observes that **Copper Ore Veins** (Mining tasks) still display the old circular bubble style.

### Current Implementation & Root Cause
- **Why Bubbles Appear**: In [`TokenBubbles.jsx:201-205`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBubbles.jsx#L201-L205):
  ```javascript
  const plated = hasHero && !fight;
  const hasCharges = usesRemaining != null;
  const showCharges = hasCharges && isHovered && !plated;
  ```
  The work plate is **only** mounted when a hero is actively working the token (`plated = true`). When a token is unworked (such as an idle Copper Ore Vein, or a vein needing a pickaxe), `plated` is false. On hover, [`TokenBubbles.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBubbles.jsx) falls back to rendering the legacy circular bubble row ([`RingBadge`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/RingBadge.jsx)).

## 5. Erroneous Charges Bubble Displayed on Enemy Tokens

### Problem Summary
Hovering over enemy tokens currently displays a circular charges bubble (e.g. showing "1" or "100"). Enemies are combat opponents that display an HP bar; they should never show a resource/station charges ring.

### Current Implementation & Root Cause
- **Enemy Definitions**: In [`data/tokens.json`](file:///c:/Users/16048/Projects/fantasy_guild_v2/data/tokens.json), enemy tokens have `tokenType: "enemy"`, but carry internal `uses: 1` (e.g., `token_goblin`, `token_wolf`, `token_crab`) or `uses: 100` (e.g., `token_cow`, `token_thorn_elemental`).
- **Bubble Condition in [`src/ui/components/board/TokenBubbles.jsx:203-211`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBubbles.jsx#L203-L211)**:
  `hasCharges = usesRemaining != null;` lacks an enemy check. When hovering over an unengaged enemy token, it displays both the HealthBar and an unwanted circular charges bubble.

### Specification for Implementation
- In [`TokenBubbles.jsx`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/TokenBubbles.jsx), update `hasCharges` to explicitly exclude enemies:
  ```javascript
  const isEnemy = getTokenType(typeId)?.tokenType === 'enemy' || !!getTokenType(typeId)?.enemy;
  const hasCharges = usesRemaining != null && !isEnemy;
  ```

## 6. Token Bar Design Review & Visual Decluttering (Owner Direction)

### Strategic Vision
The owner identified that having two separate presentation paradigms (bars when worked, circular bubbles when unworked) creates inconsistency and unnecessary visual stimuli across the playmat:
> *"Seems like the bubbles are just being used when the token is not being worked. However, I think it would be better if it was consistently displayed as the bar, and perhaps only shown on hover. I'm trying to overall cut down the amount of visual stimuli that we're presenting, as it's a little bit much right now.  
> I also noticed that there's some information that doesn't need to be on the bar, such as the output item. I think we just need to do a general planning review of the token bars and what information should be on them."*

### Key Design Pillars for Planning Agent

#### A. Unify Around the Bar Format & Retire Circular Bubbles
- Transition unworked tokens (and all gathering tasks like Mining) away from the old circular SVG `RingBadge` bubbles.
- Use a single, unified bar/plate component for both worked and unworked states.

#### B. Drastically Reduce Visual Stimuli (Show on Hover)
- At rest, tokens should remain clean and uncluttered. Floating UI badges and plates should not clutter the screen while unattended.
- The bar/plate should appear **on hover** (or stay minimal until hovered/engaged), letting the pixel art and environment breathe.

#### C. Information Architecture Review of the Token Bar
Review each cell currently in [`workPlate.js:plateCells`](file:///c:/Users/16048/Projects/fantasy_guild_v2/src/ui/components/board/workPlate.js#L125-L144):
- **Output Item (`CELL.OUTPUT`)**: **Remove or minimize**. What a token produces (Oak Wood from Oak Tree, Copper Ore from Copper Vein) is already evident from the token sprite and contextual inspection. Displaying the item icon on the bar adds clutter.
- **Progress Fill (`WorkBarFill`)**: **Keep**. Essential feedback for cycle progression.
- **Charges Remaining (`CELL.CHARGES`)**: **Keep (minimal)**. Clear count of remaining uses.
- **Problems / Blocked State (`CELL.PROBLEM`, `CELL.MISSING`)**: **Keep**. Clear indication when work cannot proceed.
- **Skill Icon / Time to Next (`CELL.SKILL`, `CELL.TIMER`)**: Keep restricted to expanded/hover states.
