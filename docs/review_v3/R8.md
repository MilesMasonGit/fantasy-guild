## 1. Plain-language summary for the owner

- **The hero sheet next to the Bank probably closes the moment you click inside it** (CR3-450). The
  bottom hero dock is still on screen, hidden under the Bank, and it keeps a "click anywhere outside
  me closes the hero sheet" rule. The Bank's own hero panel isn't "inside" the dock, so any click on
  that sheet counts as outside. The Edit button and expanding a skill row would be lost with it.
  This is the one likely player-facing bug. It needs a 30-second check in the running game.
- **The Close (X) on the Guild Hall upgrade panel does nothing you can see** (CR3-451). It clears
  the selection, and the screen instantly falls back to the same upgrade.
- **Every notification looks the same whether it is good news or an error** (CR3-452). Each toast
  type has its own colours written down, but the colours are never used. Repeated identical messages
  are also merged into one, and the "×3" count is never shown.
- **Closing things works differently everywhere** (CR3-454). Escape closes the pop-up windows, the
  bottom hero sheet and disallow mode. It does not close the Bank, the Shop, the flag-rules panel,
  the Token pop-up or the Guild Hall. Clicking outside closes some of these and not others. There
  are three different close-button looks: the red pixel-art cancel icon, a thin "X", and text buttons.
- **There are five or six separate tooltip styles** (CR3-455). The flag, Hall, quest, Token-cap and
  Upkeep tooltips share one gold-bordered look, but that look has been copied into five places
  rather than shared. The recipe gear's tooltip is drawn inside the Token, so a Token standing in
  front of it can cover it. Token alerts use a coloured bubble of their own. Everything else uses
  the browser's plain tooltip, which you ruled against for the Hall (FB-52).
- **Layering has no single rulebook** (CR3-456). `matLayers.js` orders things on the mat well, but
  everything outside the mat uses about 20 hand-typed numbers. As a result the tutorial's golden
  beacon and the Token-alert bubbles draw **on top of** pop-up windows, and the flying-loot particles
  hide for the Settings window but not for Hero Edit or the promotion ceremony.
- **13 of the Settings screen's controls do nothing** (CR3-033, re-checked properly). Four of them
  still name things that no longer exist (Tray, Card badges, Boost tiles, Packs). Your round-2 ruling
  covered four of the 13. The rest need a fresh ruling (Question Q1).
- **Text sizes in the code are not the sizes on screen** (CR3-460). A global rule snaps every size
  onto your seven Typography-Scale steps. So "9 px", "10 px" and "12 px" labels all show at 16 px,
  and the "bigger on wide screens" rules do nothing. The screens are consistent, because the snapping
  does its job. The code just can't be trusted to say what you'll see. The same goes for fonts: your
  Font Preference overrides every per-panel font choice.
- **All dev tools are properly hidden from players.** There are seven now. Round 2 kept four; MatTuner,
  PlaymatTuner and the Animation Studio are new. Every one sits behind the dev-build / Debug Mode
  switch.
- There is a fair amount of **dead wiring**: events that nothing sends, controls nobody uses, and the
  Bank's "filter by slot" machinery. It is harmless to play and is cleanup for a fix wave.

### CR3-450 — The hero sheet beside the Bank closes on the first click inside it
- **Category / Severity / Effort**: UX+WIRE · **P1** · S
- **Impact / Confidence / Score**: 4 · 0.6 (reasoned) · 2.4
- **Risk**: low — needs test: a component test that clicks inside the Bank-side sheet
- **Where**: `src/ui/components/dock/BottomHeroDock.jsx:76-104` (document `pointerdown` + Escape listeners while a hero is selected); `src/ui/ReactRoot.jsx:375-384` (the bottom dock stays mounted whenever the view is not the Guild Hall, **including while the Bank is open**); `ReactRoot.jsx:315-322`, `:421-428` (the Bank-side `BankHeroPanel` shares the same `inspectHeroId`); `src/ui/components/dock/BankHeroPanel.jsx:61-76`.
- **What**: With the Bank open, the bottom dock is covered by the Bank drawer, but it is still mounted and still listening. Its "outside" test only exempts its own `aside`, `[data-dnd-region="drawer"]`, `[data-item-id]` and `[data-bank-tab]` (`BottomHeroDock.jsx:80-88`). `BankHeroPanel` and its `HeroInspectionSheet` carry none of those markers, so any `pointerdown` on the Bank-side sheet closes it before the click lands.
  - **Knock-on 1**: the sheet's Edit pencil (`HeroInspectionSheet.jsx:150-158`) is removed before its `click` fires.
  - **Knock-on 2**: clicking the already-selected hero tab can never close it. `pointerdown` sets null, then the tab's toggle sets it again (`ReactRoot.jsx:318`).
  - The one exemption that saves some cases is `[data-item-id]` (equipment cells).
- **Evidence**: code path only. Owner ruling B10: "The Bank's vertical hero panel is left as it is" (`docs/token_lifecycle_feedback_v1.md:236`). That was a ruling on the look; this is a bug in behaviour.
- **Fix shape**: either give `BankHeroPanel`'s `aside` a marker the listener exempts, or unmount / disable the bottom dock's listeners while the Bank is open. Confirm in Session C first (open the Bank, click a hero, click a skill row).
